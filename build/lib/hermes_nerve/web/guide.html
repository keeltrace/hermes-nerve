BEGINNER WALKTHROUGH

Get a real decision engine running.

A green server light is not enough. The only reliable test makes a typed inference request and checks the model's response.

Four steps from nothing to a working decision

  1. Choose a backend. Jev is hosted; D1 and Laya can run locally. Shadow compares two engines.
  2. Review local setup. Click Review one-click setup. Inspect Python, packages, disk, model size, and any code-download warning.
  3. Install and start. Click Install dependencies & start only if needed and after reviewing the confirmation. This uses a dedicated virtual environment. Model downloads can take minutes.
  4. Run real decision test. This submits one fixed example about a duplicate charge and checks that the model returns a typed choice. Only REAL INFERENCE PASSED means the test passed. Apply the Nerve profile separately and restart Hermes.

Liquid D1: recommended local decision engine

The full LiquidAI/d1-3B checkpoint includes approximately 6.25 GB of model weights, plus PyTorch and supporting Python packages. Inference needs substantial RAM or GPU memory; CPU execution may be slow.

One-click option: The Control Panel can create a virtual environment, install its Python requirements, download the official checkpoint, launch a local System One HTTP server and run one genuine inference check.

Safety: Liquid D1 is licensed under LFM1.0 and its official Transformers loading procedure executes model-supplied Python with trust_remote_code=True. You must explicitly approve this before installation. The installer never grants administrator privileges.

Already running? If 127.0.0.1:8080 is occupied, do not replace the service. Run Check service only, then Run real decision test. An SSH-forwarded server also appears as a local port.

Official reference: LiquidAI/d1-3B model and usage guide ↗

Laya: lightweight local alternative

One-click option: Install the pinned laya==0.3.29 Python release into a dedicated environment. Start the locally bound Nerve sidecar at 127.0.0.1:8765. The first run downloads the model checkpoint. Then run a real typed-decision test.

If a Laya service is already running, do not overwrite it. Check the existing local URL and run the inference test.

Official reference: Laya typed-decisions model ↗

OpenJev: advanced, hardware-specific

OpenJev is not a small one-click model on typical consumer hardware. Published implementations have different hardware requirements. Some require large NVIDIA GPUs, a separate vLLM server, and a second decision API shim.

Start an OpenJev-compatible /v1/systemone helper on an HTTP loopback port (the Nerve default is 127.0.0.1:3000). Then choose OpenJev in More backends and run the real test. A /health result alone is insufficient.

Serving reference: Official OpenJev serving guide ↗

Generic System One

This is an interoperable decision API, not a downloadable model. Bring any server that responds to POST /v1/systemone with a JSON object containing model and typed answers. The model selector, paths and credentials are configured in the Advanced controls.

The GUI only probes HTTP loopback addresses. This protects the install wizard against accidental remote-model traffic.

Hosted Jev and Shadow mode

Jev can use OpenRouter, TypeSafe or OpenCode. Check service only does not call a hosted provider. Run real decision test makes a real provider request that may consume paid credits. If credentials are only available inside a Hermes secret scope, launch the Panel in the correct Hermes environment.

Shadow mode performs both a hosted Jev call and a separate local comparator call. It does not pass unless both return valid typed decisions. The two decision results can differ without either test failing: connectivity and schema are tested, not benchmark accuracy.

What the statuses mean

Not tested
No model request was made.
HTTP only
The port answered a health endpoint, but inference is unverified.
Real inference passed
A real request returned a valid typed answer and a reported model identity.
Inference failed
No valid typed answer returned. Inspect the backend URL, model readiness, provider account or owner-only installation logs.

Local setup logs are stored in $HERMES_HOME/nerve/local-backends/<backend>/. The model download and installation occur only after an explicit confirmation. Turning on the Nerve Reflex module does not itself download a model.
